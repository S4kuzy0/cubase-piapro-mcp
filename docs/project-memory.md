## 关键决策

- 使用底层 PPSF 二进制容器做定点修改，不经过可能丢失专有设置的通用 Project 转换。
- 原 PPSF 必须能精确二进制往返；改变歌词长度时重新计算事件及事件块长度。其他数据块须保持不变。
- VSQX 使用 lxml 保留未知节点、命名空间、CDATA 和原有样式。支持已有音符编辑以及 VSQX 插入、删除和新建乐谱。
- CPR 接入只读核心；覆盖上游按轨道名称合并的后处理，保留重名轨道。解析值为启发式观察，不作为实时控制目标标识。
- Piapro 接口动态发现窗口和菜单，不沿用旧脚本固定句柄或进程 ID。数据和文件路径操作不用坐标；本机允许在原生激活被 Windows 拒绝时，核验标题栏后点击取得焦点。
- 文件写入前后检查来源哈希，覆盖前建立实际可读取备份；只允许原文件同路径覆盖，其他输出不得已经存在。
- 不实现任意 CPR 原生写入；原生 PPSF 插入/删除音符和新增控制点需另行验证，先通过 VSQX 完成。

## 实机排错结论

- pywin32 没有 GetMenuString，使用带正确指针类型的 Win32 GetMenuStringW。
- Piapro 菜单启用状态须通过 WM_INITMENUPOPUP 刷新；后台菜单操作还需原生 WM_ACTIVATE 通知。Windows 可能拒绝改变前台焦点；已加显式开关的受限标题栏激活后备，原生菜单和文件路径仍通过消息处理。
- PPSF Events 尺寸内包含解析器不消费的尾部零终止字节。按新数组长度重写块尺寸会丢失终止字节，被真实 Piapro 拒绝。必须基于原尺寸加长度差，保留填充；仅改音高应只改变一个字节。
- PPSF 时序同时存于 Events 与 EditorDatas 的 ENOT 中。只改 Events 时长会在重载后被覆盖；现已验证对齐关系并同步 pos_tick、dur_tick、dur_tick_copy。若目标音符原有时序不一致则拒绝该音符的原生时序修改，使用 VSQX；不阻止其他正常音符。
- Piapro 原生导入会先提示覆盖当前乐曲。仅在已取得实际快照后识别此特定确认并继续；文件错误或其他未支持对话框返回明确错误。
- VSTi 的文件级混音导出被禁用，WAV 使用选中 Piapro 音轨的导出。无选中音轨时返回禁用错误。
- SDK 默认隐藏普通异常详情；可向调用者解释的 IntegrationError 继承官方 ToolError，保持 isError 标记并暴露可操作错误码。
- 导入使用按内容哈希验证的私有暂存副本，防止用户源文件在导出快照期间变化。

## 末轮反馈修复与恢复核验

早期 MIDI 绑定回调会先反映输入，无法作为真实宿主状态。驱动协议升级为 2，仅从宿主 mOnProcessValueChange 更新缓存；旧协议将返回未连接。走带改用明确的 Transport 命令，按钮脉冲留出处理间隔；混音采用 Jump 绝对模式。控制结果需连续多次回传稳定。实际测试中独奏会暂时覆盖静音，恢复时先恢复独奏、再恢复静音。

Piapro 导入同一原生快照后，VSQX 声库 program 可能重新编号；本次从 0 变为 2，但声库名称及全部区段的歌手语义一致。恢复核验比较声库实际名称映射，不能把跨导出文件的 program 当作永久标识。临时 Cubase 工程磁盘内容与复制来源仍逐字节相同。
