# 人声分离、歌声转谱与歌词对齐：选型记录

调研日期：2026-10-18，北京时间。用户随后已明确选择 A，实施与实际验收状态见 [组件说明](../audio-to-score/README.md)。以下保留当次选型依据。

## 已确认目标

用户希望先接入人声分离、自动转谱和歌词对齐，再提供网易云链接，先制作一段副歌的初音试听。数据和接口优先，下载、运行环境、缓存及测试资料保存在 E 盘；宿主验收只使用 E 盘副本，保护原工程。用户明确要求先比较 MCP 与 Skill 的利弊，由用户决定形式。

现有稳定 MCP 为 0.5.0、33 工具，已有乐谱读写、Piapro 导入导出和调教能力。音频分离、音频转谱及歌词强制对齐尚未实现。插件/参数/EQ/发送扩展继续保持开发状态，本提案不改变其发布门禁。

## 形式比较

| 选择 | 内容 | 优点 | 成本与边界 |
| --- | --- | --- | --- |
| A：MCP + Skill（建议） | 独立音频后端；MCP 提供有结构的作业接口；薄 Skill 组织副歌处理、检查和试听 | 可单独复用底层操作，也可用一句话启动完整流程；计算、工具协议和流程说明各维护一份 | 比单独 Skill 多一层工具接入；首次部署与集成验收工作量中高 |
| B：仅 MCP | 相同后端与作业接口，暂不提供流程 Skill | 适合其他 MCP 客户端和逐步调用；结果与错误可以自动检查 | 每次完整翻唱流程仍需组织工具顺序；接入工作量中 |
| C：仅 Skill + 脚本 | Skill 调用本地命令和共享后端 | 首次接入最少，适合当前 Codex 本机试用；脚本也能实现严格检查 | 对 shell、路径和本机环境约定的依赖更强；其他 MCP 客户端不能直接作为工具调用；后续接口化另需接入 |

三者可以复用同一算法实现，音质取决于模型、素材与校正，不能用包装形式判断。Skill 可以包含确定性脚本；MCP 本身不会提升识别精度或自动消除崩溃风险。官方说明：[Skills](https://developers.openai.com/plugins/concepts/skills)、[Build skills](https://developers.openai.com/plugins/build/skills)。

选定的 A 首版使用独立音频 MCP 进程，与现有 Cubase/Piapro MCP 配合。重模型在独立工作进程内运行，稳定 DAW 服务不导入 Torch 或音频模型。

## 本机与实现边界

只读检查确认 RTX 5070 Laptop、约 \(8\,\mathrm{GB}\) 显存、约 \(32\,\mathrm{GiB}\) 内存；当前 MCP 虚拟环境没有 Torch、NumPy、audio-separator 或 WhisperX。已有 E 盘 FFmpeg 可作为后续检查对象，不将“发现文件”视为已验证可用。

当前上游 audio-separator 要求 NumPy 主版本至少为二，GAME 则限制低于二，因此不应将全部依赖装进同一环境。建议独立分离环境与转谱/对齐环境，以文件和 JSON 交接；模型顺序运行、处理完释放进程，再进入宿主阶段。Torch/CUDA 与当前驱动、Blackwell GPU 的实际兼容性仍待安装验证；必要时缩小模型/片段或使用 CPU，不擅自修改系统 GPU 驱动。

首版建议本地按需运行，无数据库、常驻网页或付费 API 依赖；有模型下载、磁盘及计算耗时，速度与峰值显存尚未测量，不能给出整首实时完成承诺。上游未固定的依赖、模型变更与年轻的对齐接口都需要版本固定和样本回归，长期维护成本中等。

## 首版处理与验收建议

1. 输入本地可解码音频与已确认歌词；后续拿到网易云链接再核查可获取的音频及歌词，不预先承诺任意链接都可取得完整音频。每项输入保存哈希，所有裁剪保留原曲时间偏移。
2. 输出人声与伴奏，核验文件可解码、长度和时基。双轨分离可能仍包含和声，不自动宣称是纯主唱。
3. TIFA 对齐歌词，按语种词典生成字词/音素边界；超过模型适用上下文的片段分句处理。LRC 通常只有句级信息，不能当作逐音素真值；缺词时的 ASR 输出为待校对草稿。
4. GAME 生成音符并适配已知字边界，处理一字多音、休止及连音，保存未量化时间与浮点音高。识别不确定或读音不明确的部分返回诊断，不静默填词。
5. 将中间数据转换为现有 MCP 可读的 VSQX/MIDI，并独立回读验证。MIDI 音符不能等同于原唱完整的连续音高、颤音和表情复刻；细节调教单独验证。
6. 先用自制且有已知乐谱/歌词的短样本检验流程；分离、转谱和对齐全部在 Cubase 关闭时进行。通过后，再用 E 盘单一 Piapro 工程副本导入、完整回读、导出试听及验证恢复。结果未验收前不替换稳定 MCP 或注册生产新工具。

后台作业接口建议提供启动、状态、结果和取消，任务清单记录输入哈希、模型/版本、裁剪偏移、产物及阶段状态；接口名尚未定稿。失败不自动触发任何 DAW 操作，Skill 与 MCP 共用同一实现和检查规则。

宿主收尾必须沿用已记录的单次原生退出协议；原始崩溃与受控重入故障的逐对象关联仍未证实，不能保证厂商宿主绝不崩溃。这里只承诺隔离计算、保护原件与逐阶段验收。

## 已确认方案

用户已明确选择 A：以 audio-separator + GAME + TIFA 作为首轮验证组合，增加薄 Skill 组织完整流程；SOME 与 WhisperX 暂作备选。授权模型、环境和测试资料放 E 盘，先离线验收，再进行 E 盘 Piapro 副本验证，确认稳定后接入 Codex；原工程保持保护。
