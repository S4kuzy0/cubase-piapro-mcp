# 轨道查询崩溃隔离与回归

日期：2026-10-16，北京时间。适用本机 Cubase LE 14.0.40。

## 证据与边界

两份本机转储分别生成于 20:07 和 21:53，均为 Cubase14.exe 同一偏移处的空指针读取。后一份与轨道查询调用时间相符，当时没有加载 Piapro。没有厂商调试符号，转储偏移不能直接命名为某个官方 API 函数。

桥接代码中已确认的缺陷是：查询会向未分配的 selected channel 或类型 bank 槽读取 UID，并在 MIDI 输入回调中复用此前保存的 mapping 上下文。空工程的离线边界测试在旧实现上失败。JavaScript 异常捕获不能作为宿主原生访问违规的保护。

## 修复

- 只在有名称的宿主通道事件回调中，使用该回调传入的上下文取得并缓存 UID。空槽不读取 UID，失活时清空缓存。
- MIDI 查询只编码缓存；轨道类型 bank 的匹配也只读取缓存，不调用原生身份接口。
- 客户端先通过独立 CC 进行 `host-cache-1` 版本握手，旧驱动无响应时不发送轨道查询或重置 bank。
- 未取得实际 UID 时拒绝选轨；页面重激活更新会话标识，避免工程切换后的旧 revision 继续有效。

## 实际验证

真实驱动的 Node 边界测试覆盖空工程、仅 MIDI、MIDI 路由到 Piapro、无选中轨、删除全部轨道、同名新工程和重复查询。测试替身对空槽及查询回调中的原生读取立即报错；旧实现失败，修复后通过。它用于约束调用边界，不模拟 Cubase 音频引擎，也不能替代实机验收。

实机仅使用已保存并备份的 E 盘副本：仅含 MIDI 轨时连续查询 50 次，删除最后一轨后空工程连续查询 100 次，没有新增崩溃转储。随后移除空的 Piapro 乐器轨、再次首次加载 Piapro、添加音频/MIDI 轨、按 UID 选择、复用已有实例及模板工程切换均通过。旧 revision 和重复 Piapro 请求在实际 MCP 客户端中被拒绝。

原有声像修改及恢复、播放与停止也通过宿主反馈。训练现场先导出 PPSF 并另存完整 CPR 检查点，测试不覆盖原训练工程。恢复结果与最终自动测试数量见 [验证记录](validation.md)。本机转储、工程、音符及恢复点不上传仓库。
